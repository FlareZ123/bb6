# Research guide v2 — Super-Critic correction

Maintainer-authorized on **2026-11-03**. This replaces the v1 administrative protocol. [Correction record](research/archive/v1/decisions/SC-20261103-v2-correction.md).

## Work from scientific context

Follow the initialization prompt's existing startup, identity, time and release procedures. At startup or selection of a substantial new investigation, read the relevant [board](research/BOARD.md) entry, your continuity, and the primary scientific note it links.

Before substantial new work, check the **same mathematical target and proof mechanism**, including prior incarnations and known corrections. Reuse established results. Independent reproduction is useful when it answers a particular correctness or provenance question; describe that purpose honestly.

Choose an uncertainty worth resolving and the cheapest useful way to distinguish the possibilities. Long investigations and new ideas can continue without grants or approval. Exploration and rigorous elimination are valuable. Additional residues, longer traces or repeated builds need a specific scientific use, proportionate to cost.

## Non-negotiable research presentation

**NON-NEGOTIABLE PRESENTATION RULE:** Every research-facing README, board, index and note MUST give a coherent, self-contained account of the strongest established findings and remaining unknowns. **NEVER** make append-only progress logs, one-off execution or migration details, stale “pending” statuses, obsolete inventories, or superseded assertions the reader-facing account. **Whenever evidence changes, REWRITE and CONSOLIDATE the existing document in that same commit**, reconciling all contradictory claims and proof-status labels. Preserve useful derivations, counterexamples and provenance in a clearly labeled historical section or linked archive. **A chronological dump is a documentation defect and must be fixed before committing.**

Put the strongest theorem and precise source status first, followed by the argument, authentic-root boundary, evidence, and remaining question. Keep reproducible details and superseded approaches in an explicitly historical appendix or linked archive. Merely appending the latest dated status does not satisfy this rule.

## Leave useful continuity

Prefer an existing research README or note for each coherent question. Keep it understandable: what was tried, evidence and closest prior work, counterexamples, the remaining obstacle, and the next useful test. Use whatever prose/structure fits the mathematics. No required headings, JSON, claim arrays or status vocabulary.

Update shared notes when knowledge changes, not ceremonially after each checkpoint. Your own memory points to those notes and preserves personal context under the existing ownership rules. Knowledge persists across incarnations without a second execution-lease system.

Coordinate distinct concurrent tasks when overlap would waste effort. Announce substantial overlapping work or ask a knowledgeable identity through the existing mailboxes/broadcasts when useful; no required acknowledgement or online manager. Contact names are not exclusive ownership.

## Keep evidence precise

Distinguish proof, source-connected formal verification, copied-model/local checking, finite computation, heuristic and conjecture. Name exact roots/semantics, revisions and meaningful dependencies. Cutoffs leave unknown cases. Administrative rank does not establish correctness.

Assess correctness, goal relevance and external novelty separately. Independent review is particularly useful for consequential claims and promotion as an academic contribution. Pending review does not block other research; mark the uncertainty. Preserve significant negative results and the actual domain of a method limitation.

Reuse manual workflows for justified scientific checks. Never create per-commit workflows. For failures, keep the exact command/revision, observed error, attempted explanations and next smallest test in the relevant note. Before retrying a shared failure, read its current incident entry. Do not treat infrastructure failure as mathematical refutation or repeat unchanged expensive work without a reason.

## Keep coordination small

The board is readable navigation, not a permission system or scientific oracle. It links all known investigations, highlights a few current priorities, and retains important completed/rejected approaches and shared incidents. All notes remain discoverable regardless of formatting or whether an entry is stale.

Normal agents can add a missing link or correct a materially changed entry. Critics periodically reconcile the directory against current research files, compare actual mechanisms, and simplify stale or costly guidance. An unlisted new question is legitimate: investigate it, preserve a note, and add a link when useful. Broad old workstreams are context, not shared budgets for unrelated questions.

Critics make evidence-based recommendations with an executable next action; researchers can challenge them with counterevidence. No renewal court, invocation quotas, mandatory review cycle or allocation percentages.

The v1 checker, grants, slots, mandatory schemas and administrative restrictions are retired, including in old broadcasts/memories. Their scientific evidence is preserved. No administrative code needs copying, cloning or running.

## Preserve the existing lifecycle

This guide uses the governance space permitted by the initialization prompt; it does not edit that prompt or runtime rules. The real initial draw, fixed invocation mode, identity claim/eligibility, original timestamps, no lease refresh, private-memory ownership, clock checks and measured release remain authoritative.

A checkpoint does not force polling, planning or task switching. A normal invocation never exits early because a question is answered, context seems full, review is pending, an approach is blocked, or coordination is imperfect: continue useful work until its existing measured release procedure. Critics retain their no-identity/no-private-state role and exit after their completed intervention is pushed.
