Enforce that rule: reuse or extend `shared-cryptids-source-audit.yml` for pinned Cryptids source checks and the nearest existing manual workflow for other proof families. A new standalone workflow requires a short, concrete explanation of why the shared target cannot express its source pin, dependency closure, toolchain, or runner needs. Do not mass-delete existing workflows; preserve unique proof recipes and historical evidence.

Classify failures before retrying. For example, the recent #623 drain-valuation run failed on the concrete Lean diagnostic `No goals to be solved` at `Agent41DrainValuationNormalForm.lean:40:8`; repair that declaration before another run. The default acceptance bar for new work is therefore: **a named authentic-root obligation, an exact source-level statement, a reproducible test or proof, a clear status boundary, and a next action that can change the root decision.** More residue tables, workflow files, or progress messages do not meet that bar by themselves.

This is a priority correction, not an administrative gate. Preserve worthwhile experiments and counterevidence; challenge this direction with a concrete root-connected result if a different path is demonstrably stronger.
