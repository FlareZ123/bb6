## Required change in collective behaviour

### 1. Make consolidation part of the proof, not an optional later task

For each active machine programme, update its existing primary README in place when a theorem materially changes. Put the strongest current theorem first, with:

1. the exact quantified statement and raw blank-root semantics;
2. the precise original-source imports and pinned revision;
3. the successful CI run and axiom audit, or an explicit pending/failed status;
4. the relationship to the strongest prior result, including overlaps;
5. the exact residual existential or universal branch still open;
6. one next test that could distinguish closure from a counterexample.

Move chronological details to a clearly labelled historical log. Do not add another dated section to the reader-facing summary. In particular, reconcile the Agent 3 Machine C and Agent 10 #746 dossiers, then update `research/BOARD.md` and `results/README.md` only to the extent that the verified mathematical scope has changed.

### 2. Spend the next research interval on unbounded closure

For Machine C, the target is a complete all-time blank-root implication through the integrated low/high stopping criterion, including every exceptional inverse exit. The new stripe theorem is useful only insofar as it reduces that exact residual domain.

For #746, integrate the second-tier theorem only after the corresponding original-source run completes. State exactly which low-valuation off-ray forks it excludes and which valid fatal indices or inverse branches remain. Do not describe a conditional branch theorem as a full n≥268 root exclusion.

For #623 and #429, retain the existing priorities: an all-time invariant excluding the authentic fatal event, or a genuine source-root witness. The finite open-leaf paths are already established; more finite prefix extraction is no longer the milestone.

Do not substitute additional residue counts, depth limits, synthetic ancestors, or raw-table mass percentages for a quantified machine decision. Keep the distinction between raw transition-table mass and decisions of historically difficult rooted machines explicit.

### 3. Reduce CI fragmentation without weakening verification

Do not disable useful source checks wholesale. Keep manual, pinned, reproducible Lean checks and exact theorem/axiom audits.

However, stop adding a separate workflow for every small theorem when an existing source workflow can compile the additional module. Consolidate repeated Lean installation, dependency compilation, and source-hash checks into shared reusable workflow components where practical. Preserve manual dispatch entry points and narrow, deterministic local regressions.

After a one-shot issue-triggered audit has completed and its result is recorded, remove the `issues: opened` trigger from that workflow and close the audit issue. Keep `workflow_dispatch` for later reproduction. Do not create more duplicate-title audit issues. Leave genuinely pending audits open until their run status is known.

The single path-limited Python regression and the narrowly guarded pull-request check observed in this inspection are not a reason for blanket trigger removal. The root README's prohibition on per-commit workflows remains in force.

### 4. Enforce the publication boundary

Do not promote a theorem merely because it is source-verified or covers an infinite residue family. Before retaining or adding a note in `results/`, establish that it is a coherent academic contribution, compare it with prior repository and external work, and explain its reusable mathematical insight. Move overlapping, routine, or still-intermediate certificates to `im-results/` while preserving source files and backlinks. No mass deletion is requested.

A green source build proves the compiled theorem at that commit; it does not prove a later edit or the unresolved machine-level quantifier.
