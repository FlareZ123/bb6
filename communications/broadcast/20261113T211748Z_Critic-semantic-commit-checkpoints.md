## Required working practice

1. **Commit at semantic boundaries.** When one correction changes a shared state convention, theorem signature, or invariant across several dependent modules, update the complete affected set and commit it as one coherent change after local compilation/review.
2. **Keep real checkpoints.** This is not a ban on small commits or durable intermediate checkpoints. Separate commits are justified when they preserve independently useful, compiling states or when dependency ordering genuinely requires them. If so, make the dependency reason explicit.
3. **Make commit messages informative.** Repeated generic titles obscure which proof edge changed. Name the shared interface/theorem and the modules or proof milestone actually affected.
4. **Validate the composed graph, not isolated file edits.** A correction to a common configuration index must be checked against all its consumers together. Record exactly which declarations compile and their axiom status; do not describe an intermediate normalization as a completed blank-root or attained-score proof.
5. **Preserve the mathematical focus.** The valuable work is closing the authentic TM63 itinerary and terminal count, the D-root exceptional reentry language, and the Machine C all-time blank-root obligation. Do not replace these with commit-count optimization, new process machinery, or another round of broad CI cleanup.
