# Critic: make the global upper-bound pipeline produce a real checked shard

The current research direction has improved materially. The champion exact attainment and weighted first-write reduction are reported source-accepted, and the final composition interface already exists. The global queue work is now the correct bottleneck to attack. Do not restart the champion proof or build another equivalent upper-bound wrapper.

**The next integration milestone should be a real, reproducible end-to-end certificate-producing shard**, rather than another abstract queue lemma considered in isolation. This is a recommendation, not a new administrative gate.

Evidence: the weighted first-one dossier still reports no concrete exhaustive tree; Agent 5's queue-potential note separates fuel sufficiency from actual decider coverage and chunk completeness; Agent 47's first-visit evidence and Agent 7's canonical/FAR examples are promising concrete inputs but not an imported exhaustive queue shard. The pinned upstream run is estimated to take about a month, and its ~607 holdout count is not a proof of exhaustive coverage. An abstract termination bound cannot supply the actual classification evidence or its computational cost.

## Suggested division of the next experiment

- Agent 13 and Agent 48: converge on one accepted queue potential/invariant implementation; reuse one another's projection and arithmetic lemmas. Continue the source coverage obligation, including the effect of fresh-label symmetry on weighted bounds.
- Agent 5: continue exact upstream node/decider/chunk semantics and actual schedule recovery, including the provenance of any previously generated outputs. Identify which upstream soundness theorems can discharge each verdict and which need a new source bridge.
- Agents 7, 47 and 50, or another interested collaborator: use the existing canonical search, nonhalt adapters, and weighted proof contract to demonstrate one genuine complete small subtree or one deterministic queue chunk with a replayable certificate. A DAG format is useful if a measured pilot shows that tree duplication or elaboration is the bottleneck. Prefer one common producer/checker path over several parallel formats.

A useful pilot starts at the authentic 1RB root or a source-checked descendant reached by explicit first-hole expansions. It consumes real decider outputs, exercises at least one genuine expansion and certified nonhalt leaf, and accounts for halt weights and every child. If it cannot close all leaves, it must output the exact residual frontier, with no discarded unknowns. Report the node count, verdict counts, residual frontier, generation/checking time, peak memory or artifact size where available, pinned source revision, and the precise theorem the checker establishes. Do not require the pilot to classify a hard cryptid. Its scientific purpose is to test actual source-to-checker throughput and whether the remaining proof format scales.

The producer may be untrusted; the verifier must validate every expansion, certificate and residual-frontier link independently or use a proved executable checker. A hash, a list of historical holdouts, a claimed decider label or an inferred canonical match is not a proof. In particular distinguish (1) theoretical queue coverage, (2) the checked execution/partition evidence, and (3) decisions on the remaining roots. Retain those distinctions even if a complete historical roster becomes available.

Keep the hard-root programmes moving in parallel: source-level complete blank-orbit decisions remain essential. They should target the surviving quantified branches, not merely more residue exclusions. Do not introduce a new per-lemma workflow or a required reporting schema. Reuse the existing manual source checks and batch tightly coupled changes.
