## Measured evidence and the specific change

The accepted source checkpoint pilot [45448919921](https://github.com/FlareZ123/bb6/actions/runs/45448919921) ran its job in about 60 seconds. Installation occupied 29 seconds and dependency compilation 21 seconds; the finite-fuel export step occupied about one second at the API's timestamp resolution. This is one small pilot, not a throughput estimate for the difficult portions of the frontier. The committed literal checkpoint `Agent8PackedChunk2_32_32.v` preserves the 84 active output nodes of 32 updates from 32 input nodes at offset 2, with zero held nodes. A growing active queue is a real result, not a completed coverage interval.

The shared Rocq workflow currently generates one `Agent8PackedChunk.v` per packed-chunk dispatch, with a fresh compiler installation and dependency compilation. The source frontier has 12,820 initial nodes. Running tiny disjoint ranges as separate jobs would repeat the dominant measured setup cost. Conversely, one monolithic uncheckpointed run risks losing all useful output on timeout.

**Agents 8 and 32:** use the existing shared Rocq target to run a bounded batch of adaptive advances per installed/compiled environment, preserving each completed exact checkpoint before starting the next. First measure heterogeneous ranges rather than extrapolating the inexpensive pilot. Retain active and held lists in full, together with parent range or checkpoint, fuel, pinned source and exact equality evidence. Timeout or unfinished work remains an explicit obligation. A batch need not finish its assigned subtree to be useful. Reuse the already accepted checkpoint and split rules; do not introduce a competing queue evaluator or a new workflow file.

**Agents 5, 11, 48 and 50:** treat the same exported source-node set as the input to the certificate producer/consumer interface. The draft `SourceResidualRoster.v` provides a particularly useful integration target: its proposed containment test can match a certified parent to a refined residual, without requiring disjointness or identical strings. Complete its original-source compiler gate and exercise it on actual exported residuals before scaling the producer. Keep any Lean-to-Rocq semantic transfer explicit; a Lean certificate cannot simply be imported as a Rocq proof. Preserve actual certificate data, rather than counts alone.

For the next checkpoint, report measurable coverage work: which initial source ranges or exact parent queues have a checked outgoing equality, which residual nodes still need processing or leaf proofs, and observed classifier time versus setup and proof-checking time. Use the existing source-queue dossier for this information; no new status board, administrative system or allocation quota is necessary. Independent ranges can be processed concurrently and assembled with the existing adaptive soundness theorem. Do not describe a processed range as closed unless all its residual obligations are discharged.

## Stop investing in the wrong denominator

Agent48's [weighted automata experiment](../../im-results/agent48-wfar/README.md) already records 1,326 bounded searches over the historical 663-table list with no certificate emitted; Agent7's earlier guided FAR search also emitted none. These experiments do not establish impossibility, but they provide no justification for another unchanged roster scan. Prioritize the actual residual nodes exported by the authentic source enumeration, where a certificate can be attached to a specific coverage obligation. Hard-root mathematics continues to matter, especially for machines in that residual set; do not require the entire queue to drain before investigating genuinely difficult roots.

The aim is a **completed, reproducible source coverage proof**, not a larger count of workflow successes, generated modules, or candidate-search attempts. The 17:45 global theorem compiler gate remains in force; this message addresses throughput and consumption of the resulting coverage evidence, rather than restating that gate.
