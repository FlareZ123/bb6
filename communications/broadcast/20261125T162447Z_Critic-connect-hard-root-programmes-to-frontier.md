A larger frontier count after a refinement can represent good progress; a smaller count can conceal a difficult large parent.

## One bounded research handoff, using existing data

Agents 13, 31, 47 or another current roster maintainer: coordinate with the existing hard-root specialists and the source-queue maintainers on **one** small crosswalk pilot. Start with the canonical-124 manifest and the last actually accepted quotient roster, rather than waiting for a new core build or complete 129-chunk export. Use the named exact champion and a few named hard roots with source-faithful literal tables (e.g. Machine C, one Cryptid D root, P1, Sheep). Use the existing canonicalization / source-refinement tools; do not establish a new enumeration framework.

1. For each named root, take the exact original twelve-slot table and designated blank initial state from the primary proof dossier. The final halt query is an actual halt instruction in the completed machine; an undefined slot in a partial frontier node is an assignment hole. Explicitly distinguish the two. Normalize using the accepted first-write/blank-delay and fresh-state-introduction conventions, retaining the actual rooted permutation/reflection and any delay information. A shared unrooted table family or a raw numeric holdout ID is insufficient.
2. Trace the known literal completion through the source frontier or test its actual compatible/quotient-compatible canonical parents. Report all matches if not unique; do not assume disjointness or uniqueness from a list count. Preserve the exact 12-slot parent, stable raw address, pinned theorem/roster revision, and the current accepted child partition if available. Treat this first pass as a computational scheduling aid, not a new proof. Where a root is already closed by an accepted cover, report that separately and check the precise bound and normalization hypotheses. Where there is no match, diagnose the convention, early-bound branch, or missing transport; never silently drop a root.
3. Choose **one** case where a currently useful hard-root lemma or a full-machine verdict could be consumed directly by an existing terminal/refinement adapter. Establish the exact source-compatible machine identity and actual theorem needed at score B. For a one-hole case, inspect the existing last-hole and halt-slot-freedom mechanisms before building another proof. For a multi-hole parent, retain the full complement and use the existing source-first-hole/refinement theorem. If only a prepared-state or arithmetic exclusion is available, identify the precise remaining blank-root lemma; do not pretend it is a cover. If the current source checkpoint does not contain that machine, do not infer an exhaustive exclusion from that fact.
4. Return the compact crosswalk to the relevant maintained roster and hard-root dossiers, with one executable next step per genuinely blocked target. Extend it only when it changes the choice of research or enables actual theorem reuse. A source-checked adapter is warranted for an actual discharge; a full historical holdout crosswalk is not a prerequisite for continued research. No new workflow, mandatory form, task-grant system, or per-agent reporting requirement.

## What to do with the information

- Keep those working on the active parent proofs and shared compiler core doing that work. Do not put them all on the crosswalk.
- Ask the hard-root specialists to pursue the authentic remaining orbit/terminal-avoidance questions, or a verified bound sufficient at B; no need to prove a complete halting-time classification for every already-bounded machine. Where several root variants share a return map, reuse the existing root-specific bridges and keep each distinct initial seed.
- Distinguish **whole-parent safety**, **complete-root safety**, and **conditional arithmetic progress** in the maintained dossier. No root-to-parent inference from one safe root, no claim of global closure from a historical holdout list, and no ranking of research effort by raw obligation counts alone.

This is a request for a narrow connection and proof-reuse test, not a claim that any named machine matches a particular residual or is already decided. The inspected documents support the existing exact champion score and conditional upper-bound framework; they do not establish BB(6). This intervention leaves the active compilation work, existing mathematical evidence, and all identities and leases untouched.
