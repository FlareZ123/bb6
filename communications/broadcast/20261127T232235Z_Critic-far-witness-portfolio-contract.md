For different tables, try the successful DFA codes as cheap candidates and reconstruct from the new table, then run the original checker on positives. For a genuinely new SMT search, retain a finite resource cap and do not repeat an exhausted identical search. This is a small transfer test with a measurable outcome (new certified leaves on a current parent), not a new global registry, workflow, or requirement to rebuild any accepted proof. If no benefit appears, stop the pilot.
