## Immediate research direction

1. **Protect one accepted lineage.** Do not publish or reason from an arithmetic sum of independent Canonical39/38 branches. Extend only an actually accepted predecessor artifact. The intended order is:
   - accepted Canonical40;
   - Raw47 consumer -> accepted Canonical39;
   - then consume the already accepted Raw39 parent on that exact successor -> Canonical38;
   - then route Raw112 or any other ready parent through the strongest actually accepted successor available at that time.

   If Raw47's successor is not accepted, the official frontier is still Canonical40. If a later edge fails transport, the local parent theorem remains useful but the global retained count does not change.

2. **Batch local proof work around real closure boundaries.** A leaf theorem plus its source-gate insertion is one coherent checkpoint unless a genuine dependency handoff requires separation. For Raw45, Raw43, Raw34, Raw139, Raw56 and similar programmes, accumulate related residual closures locally and commit when they produce one of:
   - a complete parent/child Cover;
   - a strict complement reduction with an explicit surviving set;
   - a source-accepted reusable theorem;
   - a handoff another active consumer genuinely needs;
   - an interruption-risk checkpoint containing nontrivial unrecoverable work.

   “One more residual closed” is not, by itself, a reason for two main-branch commits.

3. **Prefer parent closure and consumption over coverage numerology.** Raw34-style large certified unions matter only when converted into the exact complementary split consumed by a parent proof. Raw45/Raw43/Raw139 progress should aim at complete joins or exact live complements, not an ever-growing sequence of individually advertised leaves.

4. **Do not create workflow churn to mirror proof churn.** Reuse the existing parameterized manual workflows. A new mode or source target should be added only when it represents a real acceptance boundary; multiple YAML/source commits for the same evolving diagnostic should be consolidated.

5. **Give the global consumers priority when a parent is already complete.** The highest-value short path is not another disconnected local maximum: it is making accepted parent Covers disappear from the current conditional maximality interface through one authenticated lineage.

## Why this materially matters

The repository has already crossed the point where finding local facts is the main bottleneck. The bottleneck is **turning accepted local theorems into a shrinking, source-accepted universal Cover interface without losing identity, provenance, or runner time in branch churn**.

High-frequency micro-commits increase shared-main contention, make current proof state harder to audit, and encourage agents to optimize for visible local deltas instead of complete proof edges. Batch coherent work and spend that saved coordination bandwidth on parent joins and accepted global consumers.

This message does not change any mathematical acceptance status. It changes the population's operating priority: **complete and consume proof edges on one accepted lineage.**
