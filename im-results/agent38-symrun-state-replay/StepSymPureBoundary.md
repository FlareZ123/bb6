# The `stepSym` / `stepPure` boundary in the F424/F412 exact-time route

## Finding

The pinned Cryptids source defines two different symbolic transition functions:

- `BusyBeaver.SymRunEngine.stepSym` at `HaltShared.lean:3006`, which advances through `sweepBB` / `sweepCB` / `afterSweepCB` and the Rule A/B/C accelerators.
- `BusyBeaver.SymRunEngine.stepPure` at `HaltShared.lean:3793`, which dispatches through `stepPureBB/DL/CB`.

The upstream halting checkpoints are generated by `stepSym16`, `stepSym256`, and `stepSym4096` (`HaltShared.lean:3012-3014`). The current Agent 11 `SourceCostModel.costPure` and `SourceCostCombinators.costIter` instead price and compose iterations of `stepPure`.

These are not interchangeable.

## Explicit separating state

Take

```lean
s := (.BB, [.repB1 1], [])
```

The source definitions reduce as follows:

```lean
stepPure s
  = (.BB, [], [.repB1 1])
```

because the `.repB1 k` case of `stepPureBB` moves the compressed token to the right (`HaltShared.lean:3750-3754`). In contrast,

```lean
stepSym s
  = (.CB, [], [.item (.run 1), .item (.run 1)])
```

because `stepSym` in BB mode calls `sweepBB`; the `.repB1` branch calls `eatB1`; the empty-left continuation calls `stepElemBB`; and `bumpSymR` expands `.repB1 1` into two `.run 1` tokens (`HaltShared.lean:2861-2879`, `2675-2677`, `2770-2783`, `2791-2792`). Thus `stepSym s ≠ stepPure s` by direct reduction.

For the same state, `costPure true s = 11` by the current cost table. The direct `stepSym` replay wrapper separately charges the 11-step B1 sweep and then the 1-step empty-left `stepElemBB` transition, for a total of 12. This is another concrete mismatch between the current `costPure` charge and the full `stepSym` transition.

## Consequence for the proof architecture

`costIter_exact_reaches` proves a primitive-time statement for

```lean
iterStep stepPure n s
```

It does not, by itself, prove the cost of the upstream checkpoint chain

```lean
iterStep stepSym n s
```

The JS replay (`symrun_cost_replay.cjs`) instruments `stepSym` directly: it charges `sweepBB`, `sweepCB`, and the A/B/C dispatch wrappers. This does not invalidate the replay totals; it identifies a missing formal composition.

Importantly, `costPure` is still the right building block for the internal Rule A/B/C iteration blocks: upstream `afterSweepCB` calls `iterStep stepPure` for these recognized macros. The gap is the outer `stepSym` wrapper and its sweep/fallback composition, not the usefulness of the pure-step theorem itself.

## Concrete partial closure

`im-results/agent38-symrun-state-replay/SourceExactSweepBB424.lean` now defines source-shaped costs for the outer F424 `sweepBB` and `sweepCB` functions, using the exact item-step and repeated-block witnesses from Agent 11's `SourceExactF424Core.lean`. It attempts `ReachesIn` theorems for both sweeps and derives an exact BB-mode `stepSym` theorem. This file is an uncompiled intermediate draft, not an accepted Lean result.

## Remaining closure routes

The practical route is a direct composition of source-shaped exact pieces:

1. Finish exact `sweepBB` and `sweepCB` proofs, including the terminal item step and repeated-block branches.
2. Prove exact `stepElemThenBB` composition for DL and CB fallback branches, using the source exact `stepElemDL/CB` witnesses and `sweepBB` when the intermediate mode is BB.
3. Prove exact `afterSweepCB` macro branches. Use `costIter_exact_reaches` for the internal Rule A/B/C `iterStep stepPure` blocks, together with Lean-certified affine block-cost formulas.
4. Fold the resulting `stepSym` cost along the 70,511 / 21,383 upstream checkpoint traces, then add the initial `execute` prefix and the separate final `step_DL_zero_halt` transition.

An alternative is to prove a state-dependent decomposition of each `stepSym` into a finite `stepPure` sequence and transfer both endpoint semantics and accumulated cost. This is more indirect because the sweeps normalize compressed right/left tails; endpoint equality must be established through the `encSym*_eat*` and peel normalization lemmas.

Until one of these bridges is proved, `SourceExactPureStep424.lean` is a useful internal lemma but not a proof of the full F424/F412 candidate primitive runtime.
