# The `stepSym` / `stepPure` boundary in the F424/F412 exact-time route

## Finding

The pinned Cryptids source defines two different symbolic transition functions:

- `BusyBeaver.SymRunEngine.stepSym` at `HaltShared.lean:3006`, which dispatches through `sweepBB`, `sweepCB`, `afterSweepCB`, and the Rule A/B/C accelerators.
- `BusyBeaver.SymRunEngine.stepPure` at `HaltShared.lean:3793`, which dispatches through `stepPureBB`, `stepPureDL`, and `stepPureCB`.

The upstream halting checkpoints are generated by `stepSym16`, `stepSym256`, and `stepSym4096` (`HaltShared.lean:3012-3014`). The current `SourceCostModel.costPure` and `SourceCostCombinators.costIter` instead price and compose iterations of `stepPure`.

These are not interchangeable.

## Explicit separating state

Take

```lean
s := (.BB, [.repB1 1], [])
```

The source definitions reduce as follows:

```lean
stepPure s
  = (.BB, [], [.repB1 1])
```

because the `.repB1 k` case of `stepPureBB` moves the compressed token to the right (`HaltShared.lean:3750-3754`). In contrast,

```lean
stepSym s
  = (.CB, [], [.item (.run 1), .item (.run 1)])
```

because `stepSym` in BB mode calls `sweepBB`; the `.repB1` branch calls `eatB1`; the empty-left continuation calls `stepElemBB`; and `bumpSymR` expands `.repB1 1` into two `.run 1` tokens (`HaltShared.lean:2861-2879`, `2675-2677`, `2770-2783`, `2791-2792`). Thus `stepSym s ≠ stepPure s` by direct reduction.

For the same state, `costPure true s = 11` by the current cost table. The direct `stepSym` replay wrapper separately charges the 11-step B1 sweep and then the 1-step empty-left BB transition, for a total of 12. This is another concrete mismatch between the current `costPure` charge and the full `stepSym` transition.

## Consequence for the proof architecture

`costIter_exact_reaches` proves a primitive-time statement for

```lean
iterStep stepPure n s
```

It does not prove the cost of the upstream checkpoint chain

```lean
iterStep stepSym n s
```

The JS replay (`symrun_cost_replay.cjs`) instruments `stepSym` directly: it charges `sweepBB`, `sweepCB`, and the A/B/C dispatch wrappers. The current source Lean module proves (or attempts to prove) exact costs for `stepPure` transitions. This does not invalidate the replay totals, but it leaves a formal connection missing.

## Correct closure routes

1. Define `costSym` to mirror the actual source `stepSym` branch tree. Prove one-step exact reachability for `stepSym` itself, using the `stepPure` cost theorem only for the fixed-length internal Rule A/B/C blocks and using the exact primitive BB/DL/CB witnesses for sweep/fallback branches. Then fold `costSym` along the original `stepSym` checkpoint trace.
2. Alternatively, prove a state-dependent decomposition of each `stepSym` transition into a finite `stepPure` sequence, together with equality of the accumulated primitive charge and the direct `stepSym` charge. Then the existing `costIter` theorem can be used, but the decomposition and checkpoint transfer must be formal.

Until one of these bridges is proved, `SourceExactPureStep424.lean` is a useful internal lemma but not a proof of the full F424/F412 candidate primitive runtime. The README and CI descriptions should preserve that distinction.
