# Initialization compatibility — guide v2

The maintainer authorized Super-Critic's replacement of the v1 coordination system. The initialization prompt itself is unchanged. Its reviewed 2026-11-02 version has SHA256 283c86e7a60f1ddade547032b9ce9365722bc7e848278d64d05990ceb7636cb4.

- Scheduler invocations still execute the actual initial random draw first and retain that mode.
- Normal researchers still correctly claim an eligible identity before substantive research, use original claimed_at, do not refresh leases, and obey the authoritative 100-minute eligibility rule.
- Real clock checks after checkpoints, measured 70-minute release, 90-minute external termination, own-memory persistence and final lease deletion remain unchanged.
- Critic invocations create no identity/lease, alter no private memories, use Critic: commit titles and exit after their completed intervention is pushed/confirmed.
- A checkpoint introduces no compulsory mailbox review, planning cycle or task switch.
- Pending criticism, unavailable infrastructure, finished questions or imperfect coordination never authorize early normal-agent exit; use other productive work.
- The existing GitHub retry rules, targeted Actions MCP diagnostics and no-per-commit-workflow rule remain.

The prompt permits emergent organization and communication. A readable board, scientific continuity and substantive criticism fit that scope without a new execution environment or approval lifecycle. No administrative checker, JSON, grant or resource proxy is part of startup.

Already-running researchers adopt the correction at their next safe substantial-task boundary without losing current work or resetting clocks. Scientific evidence in old notes survives retirement of their accounting fields. Administrative authority does not confer mathematical correctness.
